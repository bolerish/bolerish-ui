# Styling

bolerish/ui uses StyleX to build its styles. The npm package already contains compiled components and CSS. Choose the customization boundary you need before adding build tools.

## Start with component props

Use `variant`, `size` and semantic state props before changing appearance. For example, `Button` has a single icon size, `size="icon"`; an icon-only button still needs an accessible name. Supported props and styling targets are listed on each component page.

## CSS and inline styles

Styled components accept a string `className` and React `style` on their documented target. CSS modules, ordinary CSS and inline layout styles work without a StyleX compiler. Context providers and portals do not gain a DOM styling target.

# 스타일링

bolerish/ui는 StyleX로 스타일을 만듭니다. npm 패키지에는 이미 컴파일된 컴포넌트와 CSS가 포함됩니다. 빌드 도구를 추가하기 전에 필요한 확장 범위를 선택하세요.

## 컴포넌트 속성부터 선택하기

모양을 덮어쓰기 전에 `variant`, `size`와 의미 있는 상태 속성을 사용합니다. 예를 들어 `Button`의 아이콘 크기는 `size="icon"` 하나이며, 아이콘만 있는 버튼에도 접근 가능한 이름이 필요합니다. 지원하는 속성과 스타일 적용 대상은 각 컴포넌트 문서에서 확인하세요.

## CSS와 인라인 스타일

스타일이 있는 컴포넌트는 문서화된 대상에 문자열 `className`과 React `style`을 받습니다. CSS 모듈, 일반 CSS와 인라인 배치 스타일은 StyleX 컴파일러 없이 사용할 수 있습니다. 컨텍스트 제공자와 포털에 새로운 DOM 스타일 대상이 생기지는 않습니다.

</LocaleContent>

```tsx
import { Button } from "@bolerish/ui/button";

export function SaveButton() {
  return (
    <Button className="save-button" style={{ width: "100%" }}>
      Save
    </Button>
  );
}
```

<LocaleContent locale="en">

Put CSS overrides after the package stylesheet. Class-string order alone does not decide CSS precedence. Recheck focus, disabled, error and selected states in both themes when changing appearance.

## Author with StyleX

When your own code uses `stylex.create()`, configure a StyleX compiler for your build tool and load its generated CSS as well as the package CSS. Follow the [official installation guide](https://stylexjs.com/docs/learn/installation/) for your framework. Declare directly imported runtime and token packages as app dependencies:

</LocaleContent>

<LocaleContent locale="ko">

CSS 덮어쓰기는 패키지 스타일시트 뒤에 둡니다. 클래스 문자열 순서만으로 CSS 우선순위가 정해지지는 않습니다. 모양을 바꾼 뒤에는 두 테마의 초점·비활성·오류·선택 상태를 다시 확인하세요.

## StyleX로 작성하기

앱 코드에서 `stylex.create()`를 사용하려면 빌드 도구에 맞는 StyleX 컴파일러를 설정하고, 패키지 CSS와 함께 앱에서 생성한 CSS도 로드해야 합니다. 프레임워크 설정은 [공식 설치 안내](https://stylexjs.com/docs/learn/installation/)를 따르세요. 직접 가져오는 런타임과 토큰 패키지는 앱 의존성으로 선언합니다.

</LocaleContent>

```sh
pnpm add @stylexjs/stylex @bolerish/tokens
```

<LocaleContent locale="en">

Import named tokens directly from their `.stylex` entry. `@bolerish/tokens` ships StyleX definitions: the compiler must resolve those imports; treating the source as ordinary uncompiled runtime JavaScript can fail. Keep runtime/compiler versions compatible with the installed package.

Use `stylex.props()` on native elements and pass original StyleX styles to a component's `xstyle`. Controls restrict `xstyle` to their documented layout properties; broad appearance customization belongs to the relevant container or CSS target.

</LocaleContent>

<LocaleContent locale="ko">

토큰은 이름을 지정해 정의된 `.stylex` 경로에서 직접 가져옵니다. `@bolerish/tokens`는 StyleX 정의를 배포하므로 컴파일러가 이 가져오기를 해석해야 합니다. 소스를 컴파일하지 않은 일반 런타임 JavaScript로 처리하면 오류가 발생할 수 있습니다. 런타임·컴파일러 버전은 설치된 패키지와 호환되게 유지하세요.

일반 HTML 요소에는 `stylex.props()`를 사용하고, 컴포넌트의 `xstyle`에는 원본 StyleX 스타일을 전달합니다. 컨트롤은 `xstyle`을 문서화된 배치 속성으로 제한합니다. 더 넓은 모양 변경은 해당 컨테이너나 CSS 적용 대상에서 처리하세요.

</LocaleContent>

```tsx
import { colorVars, spacingVars } from "@bolerish/tokens/semantic.stylex";
import { Button } from "@bolerish/ui/button";
import * as stylex from "@stylexjs/stylex";

const styles = stylex.create({
  panel: {
    display: "grid",
    gap: spacingVars.space4,
    padding: spacingVars.space6,
    backgroundColor: colorVars.bgSurface,
    color: colorVars.fgPrimary,
  },
  action: { width: "100%" },
});

export function SavePanel() {
  return (
    <section {...stylex.props(styles.panel)}>
      <Button xstyle={styles.action}>Save</Button>
    </section>
  );
}
```

<LocaleContent locale="en">

Internal styles and `xstyle` are merged by the component in one StyleX call. Do not spread a separate `stylex.props()` result onto the same component and expect independent `className` and `style` spreads to merge.

## Reuse Foundations

Choose roles with [Design Token](/docs/foundations/design-token), [Layout](/docs/foundations/layout), [Spacing](/docs/foundations/spacing) and [Typography](/docs/foundations/typography). For a background on an existing element, [Gradient](/docs/foundations/gradient) provides compiled props without requiring a wrapper or StyleX compiler.

</LocaleContent>

<LocaleContent locale="ko">

컴포넌트는 내부 스타일과 `xstyle`을 한 번의 StyleX 호출로 합칩니다. 같은 컴포넌트에 별도의 `stylex.props()` 결과를 펼쳐서 각각의 `className`과 `style`이 자동으로 합쳐지기를 기대하지 마세요.

## Foundations 재사용하기

[Design Token](/docs/foundations/design-token), [Layout](/docs/foundations/layout), [Spacing](/docs/foundations/spacing), [Typography](/docs/foundations/typography)에서 역할을 선택합니다. 기존 요소에 배경을 적용할 때는 [Gradient](/docs/foundations/gradient)의 컴파일된 속성을 사용할 수 있습니다. 래퍼나 StyleX 컴파일러가 필요하지 않습니다.

</LocaleContent>
