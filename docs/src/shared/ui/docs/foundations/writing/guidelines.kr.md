# 문장 작성

구체적인 문구는 사용자가 버튼을 누르기 전에 결과를 예상하고, 문제가 생겼을 때 다음 행동을 찾게 합니다. 화면의 이름·설명·알림을 같은 작업의 흐름으로 연결합니다.

## 작성 기준

### 버튼과 입력

버튼은 “확인”만 반복하기보다 “저장”, “초대 보내기”, “프로젝트 삭제”처럼 구체적으로 씁니다. 같은 화면에서 같은 행동에는 같은 단어를 사용합니다. 입력의 이름은 레이블로 유지하고, 플레이스홀더는 입력 예시로 사용합니다.

### 메시지 구조

| 메시지    | 포함할 내용                                 |
| --------- | ------------------------------------------- |
| 오류      | 실패한 작업 + 사용자가 할 수 있는 다음 행동 |
| 빈 화면   | 아직 없는 정보 + 시작할 수 있는 행동        |
| 삭제 확인 | 삭제 대상 + 복구 가능 여부 + 실제 행동 이름 |
| 완료 안내 | 실제로 끝난 결과                            |

## 적용 예시

### 초대 보내기 문구 연결하기

입력 이름은 “이메일 주소”, 버튼은 “초대 보내기”, 완료 안내는 “초대를 보냈어요.”로 연결합니다. 실패했다면 초대가 전송되지 않았다는 사실과 다시 시도할 방법을 알립니다. 각 문구가 같은 대상을 가리키면 사용자가 결과를 다시 해석할 필요가 없습니다.

### 오류 안내 작성하기

“잘못된 값입니다”보다 “이메일 주소에 @를 포함해 주세요”가 다음 행동을 설명합니다. 하지만 API에서 확인하지 못한 원인을 추측해 단정하지 않습니다. 연결 실패와 권한 부족을 구분할 수 없다면 확인된 사실만 전달합니다.

> 레이블만 읽어도 행동을 구분할 수 있는지 확인합니다. 문장을 줄이더라도 필수 조건은 남깁니다. 같은 대상의 이름을 제목·버튼·알림에서 일치시키고, 접근 가능한 이름도 화면의 레이블과 일관되게 유지합니다.
