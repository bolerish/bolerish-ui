# Banner

Keep an important condition visible while people continue working on the page.

Place the notice near the affected area and include a next step when one exists. Use Toast for a brief completion message.

> A dismissible notice must not remove the only way to recover from a blocking error.

## 사용 가이드

### 주요 속성

| 속성       | 기본값     | 값                    | 용도                                                                                          |
| ---------- | ---------- | --------------------- | --------------------------------------------------------------------------------------------- |
| `size`     | `md`       | `sm`, `md`            | 메시지 영역의 여백과 밀도를 선택합니다.                                                       |
| `announce` | 설정 안 함 | `polite`, `assertive` | 뒤늦게 추가·변경되는 안내를 보조 기술에 알립니다. assertive는 즉시 주의가 필요할 때만 씁니다. |

### 사용할 때

연결 문제나 예정된 작업 중단처럼 계속 확인해야 하는 페이지·영역 상태에 사용합니다. 영향을 받는 영역 가까이에 둡니다. 짧은 결과 안내는 [Toast](/docs/components/toast), 특정 입력값의 오류는 `FieldError`를 사용합니다.

### 문구와 행동

무슨 일이 일어났고 작업에 어떤 영향을 주며 무엇을 할 수 있는지 씁니다. `action`에는 재시도처럼 관련된 다음 행동을 넣습니다. 상태 안내에 무관한 홍보나 명령을 섞지 않습니다.

기본 크기인 `md`는 제목과 설명을 담습니다. 내용을 무리 없이 읽을 수 있는 짧은 안내에는 `sm`을 사용합니다. `Banner`에는 의미별 `variant` 속성이 없습니다. 경고·오류 변형이 내장된 것처럼 안내하지 않습니다.

### 상태 알림

> 처음부터 표시되는 안내에는 별도의 상태 알림 역할을 지정하지 않아도 됩니다. 페이지가 열린 뒤 추가되거나 갱신되는 일반 상태는 `announce="polite"`, 긴급한 중단 안내는 `announce="assertive"`를 사용합니다. `role`을 명시하면 `announce`가 정한 역할보다 우선합니다. 같은 일을 `Banner`와 Toast에서 중복으로 읽어 주지 않습니다.

## Usage guidelines

### Props

| Prop       | Default | Values                | Meaning                                                                                      |
| ---------- | ------- | --------------------- | -------------------------------------------------------------------------------------------- |
| `size`     | `md`    | `sm`, `md`            | Controls notice spacing and density.                                                         |
| `announce` | Unset   | `polite`, `assertive` | Announces a dynamically added or updated notice. Reserve assertive for urgent interruptions. |

### When to use

Use `Banner` for a page or section condition users need to keep in view, such as a connection problem or an upcoming interruption. Place it near the affected area. Use [Toast](/docs/components/toast) for a brief result and `FieldError` for a specific invalid input.

### Message and action

State what happened, how it affects the task, and what the user can do. Use the `action` slot for a relevant next step, such as Retry. Keep unrelated promotions or commands out of a status message.

The default `md` size supports a title and description. Use `sm` for compact guidance when the message still fits comfortably. `Banner` has no semantic `variant` prop; do not imply that warning or error variants are built in.

### Announcements

> Static guidance does not need a live announcement. For a message added or updated after the page loads, use `announce="polite"` for routine status and `announce="assertive"` only for urgent interruption. An explicit `role` overrides the role selected by `announce`. Avoid announcing the same event through both `Banner` and Toast.
