# Theming

Components share semantic color and shadow tokens. The installed stylesheet includes light and dark values; changing the theme updates surfaces, text, boundaries and overlays together.

## Apply a color mode

Light is the default. Apply `themeClassNames.light` or `themeClassNames.dark` to `html` after loading the package CSS. The exported classes also set the matching `color-scheme`. A `.dark` class by itself does not activate the package theme.

</LocaleContent>

<LocaleContent locale="ko">

# 테마

컴포넌트는 의미 기반 색상·그림자 토큰을 공유합니다. 설치한 스타일시트에 라이트·다크 값이 포함되어 있어 테마를 바꾸면 표면, 글자, 경계와 오버레이가 함께 바뀝니다.

## 색상 모드 적용하기

기본은 라이트입니다. 패키지 CSS를 로드한 뒤 `html`에 `themeClassNames.light` 또는 `themeClassNames.dark`를 적용합니다. 내보낸 클래스에는 해당 모드의 `color-scheme`도 포함됩니다. `.dark` 클래스만 붙여서는 패키지 테마가 활성화되지 않습니다.

</LocaleContent>

```tsx
import { themeClassNames } from "@bolerish/ui/theme";

<html className={themeClassNames.dark}>
  <body>{children}</body>
</html>;
```

<LocaleContent locale="en">

Use your framework's document or root layout for this markup. Applying the theme to `html` lets dialogs and menus rendered through a portal inherit the same tokens. Keep unrelated classes when changing modes: replace the previous theme's classes rather than the entire `className`.

## System preference and SSR

Your app owns the `light`, `dark` and `system` choice, saved preferences and the initial document theme. Resolve `system` with `matchMedia("(prefers-color-scheme: dark)")` in the browser and listen for changes only while system mode is selected.

For SSR, a saved cookie can provide an explicit initial mode. Keep the initial server and client markup consistent, then resolve unavailable browser preferences after hydration. A pre-hydration theme script is an app-level alternative that must match your framework and CSP. Do not read `window` during server rendering.

## Fonts, density and motion

These public CSS variables inherit from the document. Choose fonts and a density for your app; they do not require a StyleX compiler.

</LocaleContent>

<LocaleContent locale="ko">

이 마크업은 프레임워크의 문서 또는 루트 레이아웃에 적용합니다. 테마를 `html`에 두면 포털로 렌더링되는 대화상자와 메뉴도 같은 토큰을 상속합니다. 모드를 바꿀 때는 이전 테마 클래스만 교체하고 다른 클래스는 보존하세요.

## 시스템 설정과 SSR

`light`, `dark`, `system` 선택과 설정 저장, 첫 문서의 테마는 앱이 관리합니다. 브라우저에서 `matchMedia("(prefers-color-scheme: dark)")`로 시스템 모드를 확인하고, 시스템 모드를 선택한 동안에만 변경을 구독합니다.

SSR에서는 저장한 쿠키로 명시적인 초기 모드를 정할 수 있습니다. 서버와 클라이언트의 첫 마크업을 일치시키고 서버가 알 수 없는 브라우저 설정은 하이드레이션 후 확인하세요. 하이드레이션 전 테마 스크립트를 사용한다면 프레임워크와 CSP에 맞춰야 합니다. 서버 렌더링 중에는 `window`를 읽지 마세요.

## 글꼴·밀도·모션

다음 공개 CSS 변수는 문서에서 상속됩니다. 앱에 맞는 글꼴과 밀도를 선택하세요. StyleX 컴파일러는 필요하지 않습니다.

</LocaleContent>

```css
:root {
  --bolerish-font-body: "Your Sans", sans-serif;
  --bolerish-font-heading: "Your Sans", sans-serif;
  --bolerish-density: 1;
}
```

<LocaleContent locale="en">

Load your font separately. Default density is `1`; compact is `0.875`. Keep the default `rem` unit to follow root text-size preferences. Density does not shrink every accessibility target.

Motion follows the OS by default. `data-bolerish-motion="off"` on `html` reduces motion; `on` explicitly overrides the OS and should only follow an end-user choice. See [Motion](/docs/foundations/motion) and [Accessibility](/docs/foundations/accessibility).

## Select a surface treatment

Set `data-bolerish-surface="solid"` or `"liquid"` on `html`. This is independent of light/dark themes and component variants. Panels, resting controls and floating surfaces have different transparency and blur strengths. Primary/destructive fills, selection, error and disabled treatments keep their semantic roles.

```tsx
<html className={themeClassNames.dark} data-bolerish-surface="liquid">
  <body>{children}</body>
</html>
```

A nested `data-bolerish-surface="solid"` region can opt out. Portals mounted outside that region follow `html`, so set the app-wide choice on the document. Omitting the attribute keeps the existing behavior, including `Card variant="translucent"`.

Liquid uses CSS transparency, backdrop blur, a bright rim and inner reflection without refracting the background image; browsers without the required features, reduced-transparency preferences and forced-color modes use solid fallbacks. Keep text contrast readable over your own backgrounds. See the [Card comparison](/docs/components/card#global-surface-modes).

## Extend the palette

For a custom app surface, choose existing [Color](/docs/foundations/color) roles before adding values. Use [Styling](/docs/styling) for StyleX token imports. Generated StyleX class and variable names are not stable customization hooks; use exported tokens and the documented CSS variables.

</LocaleContent>

<LocaleContent locale="ko">

글꼴 파일은 별도로 로드합니다. 기본 밀도는 `1`, compact는 `0.875`입니다. 루트 글자 크기 설정을 따르려면 기본 `rem` 단위를 유지하세요. 밀도가 모든 접근성 대상 크기를 줄이지는 않습니다.

모션은 기본적으로 OS 설정을 따릅니다. `html`의 `data-bolerish-motion="off"`는 움직임을 줄입니다. `on`은 OS 설정까지 덮어쓰므로 사용자가 직접 선택했을 때만 적용하세요. [Motion](/docs/foundations/motion)과 [Accessibility](/docs/foundations/accessibility)를 참고하세요.

## 표면 표현 선택하기

`html`에 `data-bolerish-surface="solid"` 또는 `"liquid"`를 설정합니다. 라이트·다크 테마와 컴포넌트 배리언트는 별도로 유지됩니다. 패널, 기본 상태의 컨트롤과 떠 있는 표면은 서로 다른 투명도·블러 강도를 사용합니다. 주요/위험 행동의 채움색과 선택·오류·비활성 표현은 의미를 유지합니다.

```tsx
<html className={themeClassNames.dark} data-bolerish-surface="liquid">
  <body>{children}</body>
</html>
```

하위 영역의 `data-bolerish-surface="solid"`로 부분 적용을 해제할 수 있습니다. 영역 밖에 마운트되는 포털은 `html` 설정을 따르므로 앱 전체 선택은 문서에 두세요. 속성을 생략하면 `Card variant="translucent"`를 포함한 기존 동작을 유지합니다.

Liquid는 CSS 투명도·배경 블러에 밝은 가장자리와 안쪽 반사광을 더하며, 배경 이미지를 굴절시키지는 않습니다. 필요한 기능이 없는 브라우저, 투명도 줄이기 설정과 강제 색상 모드에서는 불투명한 표면으로 대체합니다. 앱 배경 위의 글자 대비는 별도로 확인하세요. [Card 비교 예제](/docs/components/card#global-surface-modes)를 참고하세요.

## 팔레트 확장하기

앱의 새로운 표면에는 값을 추가하기 전에 [Color](/docs/foundations/color)의 기존 역할을 선택합니다. StyleX 토큰 가져오기는 [스타일링](/docs/styling)을 확인하세요. 생성된 StyleX 클래스·변수 이름은 안정적인 확장 지점이 아닙니다. 내보낸 토큰과 문서화한 CSS 변수를 사용하세요.

## Ocean brand theme

`themeClassNames.ocean` is a precompiled light brand treatment. Primary actions, action text and focus use blue; feedback and other semantic roles retain their defaults. Replace the previous theme on `html`. It does not automatically switch to a dark brand theme.

The preview scopes Ocean to inline content. In an app, apply it to the document root so portaled dialogs, menus and notifications inherit the same tokens.

</LocaleContent>

## Ocean 브랜드 테마

`themeClassNames.ocean`은 미리 컴파일된 라이트 계열 브랜드 테마입니다. 주요 행동·행동 문구·포커스는 파란색을 사용하고 피드백과 나머지 의미 역할은 기본값을 유지합니다. `html`의 이전 테마를 교체하며 어두운 브랜드 테마로 자동 전환하지는 않습니다.

미리보기는 내부 콘텐츠에만 Ocean을 적용합니다. 앱에서는 포털로 렌더링하는 대화상자·메뉴·알림도 같은 토큰을 받도록 문서 루트에 적용하세요.

</LocaleContent>

```tsx
import { themeClassNames } from "@bolerish/ui/theme";

<html className={themeClassNames.ocean}>
  <body>{children}</body>
</html>;
```

## Create a brand theme

Custom themes require a StyleX compiler; shipped `themeClassNames` do not. Install the runtime and tokens as app dependencies, and the Vite integration as a development dependency. Keep versions compatible with the installed UI package.

Define overrides at module scope in a `.stylex.ts` file. `createTheme` accepts partial overrides: omitted roles inherit the active values (the token defaults on an unthemed document). Review action background, its foreground, state layers and focus together.

</LocaleContent>

<LocaleContent locale="ko">

## 브랜드 테마 제작하기

직접 만드는 테마에는 StyleX 컴파일러가 필요하며 제공된 `themeClassNames`에는 필요하지 않습니다. 런타임·토큰은 앱 의존성으로, Vite 통합은 개발 의존성으로 설치하고 UI 패키지와 호환되는 버전을 사용하세요.

`.stylex.ts` 파일의 모듈 범위에서 토큰을 재정의합니다. `createTheme`은 일부 역할만 바꿀 수 있으며 생략한 역할은 현재 범위의 값을 상속합니다. 문서 루트에 별도 테마가 없으면 토큰 기본값입니다. 행동 배경과 전경·상태 레이어·포커스를 함께 검토하세요.

</LocaleContent>

```package-install
npm install @stylexjs/stylex @bolerish/tokens
pnpm add @stylexjs/stylex @bolerish/tokens
yarn add @stylexjs/stylex @bolerish/tokens
bun add @stylexjs/stylex @bolerish/tokens
```

```package-install
npm install --save-dev @stylexjs/unplugin
pnpm add -D @stylexjs/unplugin
yarn add --dev @stylexjs/unplugin
bun add --dev @stylexjs/unplugin
```

```ts
// vite.config.ts — add to the app's existing React/Vite configuration
import stylex from "@stylexjs/unplugin/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [stylex({ useCSSLayers: false })],
  optimizeDeps: { exclude: ["@bolerish/tokens"] },
});
```

```ts
import { colorVars } from "@bolerish/tokens/semantic.stylex";
import * as stylex from "@stylexjs/stylex";

export const brand = stylex.createTheme(colorVars, {
  bgActionPrimary: "#00458C",
  bgActionPrimaryHover: "#00458C",
  fgOnActionPrimary: "#FFFFFF",
  fgAction: "#00458C",
  strokeAction: "#00458C",
  strokeFocus: "#00458C",
  interactionFocus: "#00458C",
});
```

```tsx
// Root.tsx — custom theme composition, without a competing color theme
import * as stylex from "@stylexjs/stylex";
import { colorVars, typo } from "@bolerish/tokens/semantic.stylex";
import { lightShadowTheme } from "@bolerish/tokens/themes.stylex";
import { brand } from "./brand.stylex";

const styles = stylex.create({
  document: {
    backgroundColor: colorVars.bgCanvas,
    color: colorVars.fgPrimary,
    fontFamily: typo.fontFamilyBody,
    colorScheme: "light",
  },
});

export function Root({ children }: { children: React.ReactNode }) {
  return (
    <html {...stylex.props(brand, lightShadowTheme, styles.document)}>
      <body>{children}</body>
    </html>
  );
}
```

<LocaleContent locale="en">

Keep `useCSSLayers: false` in the app compiler: with StyleX 0.19, a separately compiled theme layer cannot override the unlayered token defaults in the package CSS.

Load both the package CSS (`@import "@bolerish/ui";`) and CSS generated by the app compiler. Apply one color theme per element; class-string order does not determine the cascade. Keep color-scheme, typography and shadows appropriate to the theme. A nested region cannot theme portals mounted outside it. Generated CSS variable names are not a customization API.

Validate complete default/light-map parity, text/control contrast, focus and hover/pressed/disabled states, and opened overlays. Default-example WCAG axe scans and separate keyboard contracts are release gates. Passing axe does not establish complete accessibility or contrast for arbitrary backgrounds.

</LocaleContent>

<LocaleContent locale="ko">

앱 컴파일러는 `useCSSLayers: false`로 설정하세요. StyleX 0.19에서 별도 컴파일한 테마를 레이어에 넣으면 패키지 CSS의 레이어 없는 토큰 기본값을 덮어쓰지 못합니다.

패키지 CSS(`@import "@bolerish/ui";`)와 앱 컴파일러가 생성한 CSS를 함께 로드하세요. 요소마다 색상 테마 하나를 적용하고 클래스 문자열 순서에 기대지 않습니다. 명암 체계에 맞는 `color-scheme`·타이포그래피·그림자를 유지하세요. 중첩 영역 밖에 마운트된 포털에는 그 영역의 테마가 적용되지 않습니다. 생성된 CSS 변수명은 확장 API가 아닙니다.

전체 기본값/라이트 맵 일치, 글자·컨트롤 대비, 초점과 호버·누름·비활성 상태, 열린 오버레이를 검증하세요. Default 예제의 WCAG axe 검사와 별도 키보드 계약은 릴리스 조건입니다. axe 통과가 접근성 전체나 임의 배경에서의 대비를 보장하지는 않습니다.
